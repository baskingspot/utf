# Baseline: simdutf, Zig std, Rust, and Go, 2026-10-30

The first `just bench-compare` run, before this package has any SIMD function, so the `utf` arm skipped every operation. It sets the bar each wave-1 piece is measured against, and it shows where the comparison arms beat simdutf.

- Machine: Amp orb, KVM guest, Intel Xeon @ 2.60GHz (Ice Lake server, family 6 model 106, AVX-512 with VBMI2), 4 vCPUs (2 cores, 2 threads each); every arm pinned to CPU 3.
- simdutf 9.2.1 (nixpkgs), kernel `icelake`; Zig 0.16.0 ReleaseFast for the host CPU; Rust 1.99 with `simdutf8` 0.1.5, `encoding_rs` 0.8.44, `base64-simd` 0.8.0, `-C target-cpu=native`; Go 1.26.10.
- Command: `just bench-compare` (6 rounds, all six operations, `BENCHTIME_MS=100`). Raw output in `zig-out/bench-compare/` on the orb that ran it; the benchstat table and RSS table are below verbatim.

## Takeaways

- Non-ASCII text (the eight non-Latin scripts): simdutf validates at 16.4–16.6 GB/s, 8–37× Zig std and 13–28× Go, and 1.2–1.3× Rust's `simdutf8` (12.8–13.7). It transcodes at 3.4–4.9 GB/s from UTF-8 and 4.9–14.5 from UTF-16, 3–21× `encoding_rs` (0.5–1.5) and 6–41× std and Go.
- Short ASCII validation: simdutf loses. At 16 bytes it does 2.9 GB/s, Rust's `simdutf8` 3.3; at 64 and 256 bytes std is 1.4–1.6× simdutf and Rust 1.6–1.9×. The checked validator (`validate_utf8_with_errors`) is slower still on short inputs: 0.85 GB/s at 16 bytes and 6.6 at 256, where every other arm is faster, Go included. So this package's short-input bar is the fastest of simdutf, std, and Rust, not simdutf alone. Why simdutf is slow there is not measured; its per-call dispatch through the active implementation is a likely part.
- Long ASCII: `simdutf8` validates 64 KiB of ASCII at 102 GB/s to simdutf's 45 (94 to 56 in the error variant); Zig std converts ASCII UTF-8 to UTF-16 at 21–24 GB/s to simdutf's 16.
- Base64: simdutf leads from 64 bytes up, 30–33 GB/s decoding and 22–32 encoding at 4–64 KiB; `base64-simd` holds 9–10, std 2–3, Go 1–1.5. At 16 bytes std and Rust decode faster than simdutf (1.5–1.6 vs 1.1 GB/s), and at 64 bytes Rust does too.
- Peak RSS: Zig std is the floor, the inputs and buffers plus little else (2.5–5.6 MiB). simdutf adds 2.7–3.8 MiB, mostly libstdc++ and simdutf's library; Rust 1.4–3.3; Go 1.8–6.2, most on the conversions.
- Run-to-run variance: an earlier run of the same harness an hour before had simdutf's base64 rows up to 44% higher (46.6 GB/s encoding 4 KiB, 43.7 decoding 64 KiB) with the same under-10% spread within the run, on a shared KVM guest. Compare arms within one run, and A/B changes interleaved, as `bench-compare` does; do not compare numbers across runs.
